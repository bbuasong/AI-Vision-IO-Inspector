# VLAD_HD_Inference_Mat 학습중 상태 전달

기준일: 2026-08-24
기준 문서: `VLAD_HD_Inference_Mat수정-2026-08-07.md` (이 문서가 그 사양을 덧붙인다)

## 1. 배경

벤더 요청은 다음과 같다.

> 그 스크립트가 실행중임을 알려주는 값을 받을 수 있을까요, 검사 input json에서?
> 학습 도중의 검사를 CV 사용한 간략 검사로 대체하려고 하는데,
> 이 로직을 구성하려면 현재 학습이 진행중인지 아닌지 알 수 있는 값이 필요합니다.

학습이 도는 동안에는 GPU와 모델 파일을 학습이 잡고 있어 정식 AI 추론을 그대로 돌릴 수 없다.
SDK가 그 구간만 OpenCV 기반 간이 검사로 대체하려면, **호출 시점에 학습이 도는지를 SDK가 알아야 한다.**

앱은 학습 프로세스를 직접 띄우고 관리하므로 이 상태를 정확히 안다.
따라서 앱이 요청 JSON에 실어 보낸다.

## 2. 변경 요약

| 구분              | 변경 전                      | 변경 후                        |
|-------------------|------------------------------|--------------------------------|
| 학습 중 검사 요청 | 앱이 차단. SDK까지 가지 않음 | 앱이 통과시킴                  |
| 요청 JSON         | `trainingRunning` 없음       | `trainingRunning` 추가         |
| 학습 중 검사 결과 | `ERROR`로 저장               | 평상시 검사와 똑같이 판정·저장 |

**앱이 막고 있던 것을 푸는 변경이 함께 필요하다.** 지금은 학습 중이면 사진을 찍기 전에
앱이 `ERROR`로 끝내므로, 필드만 추가하면 값이 `1`로 나가는 경우가 아예 생기지 않는다.

### 2.1 앱은 학습 여부로 아무것도 다르게 하지 않는다

이번 결정의 핵심이다. **앱이 하는 일은 `trainingRunning` 값을 실어 보내는 것 하나뿐이다.**

| 항목      | 학습 중                 | 평상시                  |
|-----------|-------------------------|-------------------------|
| 캡처      | 같음                    | 같음                    |
| 요청 JSON | `trainingRunning`만 `1` | `trainingRunning`만 `0` |
| 결과 파싱 | 같음                    | 같음                    |
| 판정 기준 | 같음                    | 같음                    |
| 이력 저장 | 같음                    | 같음                    |

경고 이벤트도, 별도 표시도, 별도 임계값도 두지 않는다.
**값 하나만 다르고 나머지는 같은 검사다.**

## 3. 요청 JSON에 추가하는 필드

### 3.1 필드 정의

| 키                | 타입 | 값           | 필수 | 의미                                 |
|-------------------|------|--------------|------|--------------------------------------|
| `trainingRunning` | int  | `0` 또는 `1` | 필수 | `0` = 학습 안 함, `1` = 학습 진행 중 |

- `viewJudge`와 같이 **정수 0/1**로 둔다. 기존 사양의 표기 방식을 따른다.
- 요청 전용 필드다. **DLL은 이 값을 갱신하지 않는다.**
- 위치는 `viewName` 다음이다.

### 3.2 요청 예시 — 학습 안 하는 평상시

```json
{
  "partNo": "93HN-30050",
  "viewName": 1,
  "trainingRunning": 0,
  "viewJudge": 0,
  "score": 0.00,
  "scoreThreshold": 95.00,
  "dimensions": {
    "width": 0.00,
    "depth": 0.00,
    "height": 0.00
  },
  "measurementPoints": [],
  "measurements": []
}
```

### 3.3 요청 예시 — 학습 도는 중

```json
{
  "partNo": "93HN-30050",
  "viewName": 1,
  "trainingRunning": 1,
  "viewJudge": 0,
  "score": 0.00,
  "scoreThreshold": 95.00,
  "dimensions": {
    "width": 0.00,
    "depth": 0.00,
    "height": 0.00
  },
  "measurementPoints": [],
  "measurements": []
}
```

`trainingRunning` 외의 모든 필드는 평상시와 같다. SDK는 이 값만 보고 경로를 고르면 된다.

### 3.4 버퍼 크기

요청 버퍼는 8192 byte 고정이다. 이번에 늘어나는 양은 `,"trainingRunning":0` = **21 byte**다.
현재 실제 요청은 181~182 byte이므로 여유는 충분하다. 기존 상한 검사는 그대로 둔다.

## 4. 앱이 `1`을 넣는 기준

앱은 `TrainingProcessService.IsRunning` 하나로 판단한다.

```
_process != null && !_process.HasExited
```

즉 **학습 프로세스가 떠 있고 아직 종료되지 않은 동안** `1`이다.

| 시점                              | `trainingRunning` | 근거                |
|-----------------------------------|-------------------|---------------------|
| 평상시                            | `0`               | 학습 프로세스 없음  |
| 학습 시작 ~ 프로세스 종료 전      | `1`               | `IsRunning == true` |
| 프로세스 종료 후 VLAD 재초기화 중 | 해당 없음         | 4.1 참고            |
| 재초기화 완료 후                  | `0`               | 프로세스 없음       |

### 4.1 재초기화 구간은 SDK가 신경 쓰지 않아도 된다

학습이 끝나면 앱은 다음 순서로 VLAD를 다시 올린다.

```
DONE 수신 -> Process.Exited 대기 -> ExitCode 0 확인 -> VLAD 재초기화
```

이 구간에는 `IsRunning`이 이미 `false`지만 SDK를 쓸 수 없다.
앱은 이 구간을 `VladRuntimeLifecycleService.OperationSyncRoot` 잠금으로 막는다.
검사 호출은 잠금 앞에서 **대기**하다가 재초기화가 끝난 뒤에 들어간다.

따라서 **재초기화 중에는 SDK에 요청이 도달하지 않는다.** SDK는 이 상태를 따로 다룰 필요가 없다.

## 5. SDK가 해야 할 일

| `trainingRunning` | SDK 동작                     |
|-------------------|------------------------------|
| `0`               | 기존과 동일한 정식 AI 추론   |
| `1`               | OpenCV 기반 간이 검사로 대체 |

간이 검사도 결과 자리(`viewJudge`, `score`, `dimensions`, `measurements`)를 **같은 규칙, 같은 척도로**
채운다. 앱은 결과를 받은 뒤 학습 여부를 보지 않고 평상시와 똑같이 파싱·판정·저장한다(2.1절).

따라서 두 경로의 결과가 같은 자를 쓰지 않으면 판정이 어긋난다. 6절의 두 항목이 그 확인이다.

## 6. 협의가 필요한 사항

앱이 두 경우를 구분하지 않기로 했으므로, **SDK 쪽에서 두 경로의 결과가 같은 규칙을 지켜야 한다.**
아래 두 가지는 **아직 확정되지 않았다.** 회신에서 정해야 한다.

### Q-1. 간이 검사의 `score`를 같은 자로 볼 수 있는가 (`Q-039`)

앱은 학습 중이든 아니든 **같은 `scoreThreshold` 하나로 판정한다.**
따라서 정식 AI의 `score`와 간이 CV의 `score`가 **같은 척도여야 한다.**

- 같은 척도인가
- 같지 않다면 SDK가 간이 검사 결과를 정식과 같은 자로 환산해서 돌려줄 수 있는가

앱에 간이 검사용 임계값을 따로 두는 방식은 쓰지 않는다.

### Q-2. 간이 검사도 측정부를 채우는가 (`Q-040`)

`measurementPoints`를 보냈을 때 간이 검사도 `measurements`를 같은 형식으로 채워야 한다.
앱은 학습 여부를 보지 않고 측정부 판정을 그대로 수행하기 때문이다.

채울 수 없다면 그 사실을 알려 주어야 한다. 앱의 측정부 판정 처리를 다시 정해야 한다.

### 관련 — `score` 척도 문제

현재 SDK는 결과 `score`를 사양(0~100)이 아니라 **0~1**로 돌려주고 있고,
`scoreThreshold`는 0~100으로 받고 있어 `scoreThreshold > 0`이면 `score`가 항상 `0`으로 돌아온다.
이 건은 별도로 회신을 기다리는 중이다. 간이 검사를 붙이기 전에 함께 정리해야 한다.

## 7. 앱 코드 변경 위치

| 파일                                                      | 변경                        |
|-----------------------------------------------------------|-----------------------------|
| `VladVisionInferenceEngine.BuildInspectionContextJsonV11` | `trainingRunning` 필드 추가 |
| `VladVisionInferenceEngine.Inspect`                       | 학습 중 차단 해제           |
| `InspectionWorkflowService.RunInspection`                 | 학습 중 분기 전체 삭제      |

`Warmup`의 학습 중 건너뛰기는 **그대로 둔다.** 깨우기는 첫 검사를 빠르게 하려는 것이라
학습 중에 굳이 할 이유가 없다.

## 8. 검증 방법

| 순서 | 확인할 것                                                                       |
|------|---------------------------------------------------------------------------------|
| 1    | 평상시 검사 -> `vlad-hd-json` 로그의 요청에 `"trainingRunning":0`               |
| 2    | 학습 시작 후 검사 -> 요청에 `"trainingRunning":1`, 검사가 `ERROR`로 끝나지 않음 |
| 3    | 학습 중 검사 결과가 간이 검사 결과로 채워져 돌아옴                              |
| 4    | 학습 종료 직후 재초기화 구간에 검사 -> 대기했다가 재초기화 후 정상 수행         |
| 5    | 재초기화 완료 후 검사 -> 요청에 `"trainingRunning":0`                           |

2번과 4번이 이번 변경의 핵심이다. 특히 4번은 잠금이 제대로 걸리는지 보는 항목이라
학습 종료 시점에 맞춰 검사를 눌러 확인해야 한다.
