# VLAD_HD_Inference_Mat 요청 JSON 확장 요청

발신: 링크제네시스 응용 개발
수신: AI 솔루션 개발팀
기준일: 2026-09-03
기준 문서: `VLAD_HD_Inference_Mat수정-2026-08-07.md`

검사 요청 JSON에 **두 가지**를 추가하려고 합니다. 검토 부탁드립니다.

1. 학습 진행 여부 (`trainingRunning`)
2. 측정부 항목 구분 (`itemType`) 과 내경·외경 좌표 규칙

두 항목 모두 **요청 전용**입니다. 결과 자리(`viewJudge`, `score`, `dimensions`, `measurements`)의
구조는 바뀌지 않습니다.

---

## 1. 학습 진행 여부 — `trainingRunning`

### 1.1 배경

학습 도중의 검사를 OpenCV 간이 검사로 대체하시려면 호출 시점에 학습이 도는지 알아야 한다고
요청 주셨습니다. 학습 프로세스를 띄우고 관리하는 쪽이 앱이므로 앱이 실어 보냅니다.

### 1.2 필드

| 키                | 타입 | 값           | 위치            | 갱신                 |
|-------------------|------|--------------|-----------------|----------------------|
| `trainingRunning` | int  | `0` 또는 `1` | `viewName` 다음 | DLL 이 갱신하지 않음 |

`0` = 학습 안 함, `1` = 학습 진행 중. `viewJudge` 와 같이 정수 0/1 로 둡니다.

### 1.3 앱이 `1` 을 넣는 기준

학습 프로세스가 떠 있고 아직 종료되지 않은 동안입니다.

**학습 종료 후 VLAD 재초기화 구간은 신경 쓰지 않으셔도 됩니다.** 그 구간에는 앱이 잠금으로
검사 호출을 대기시키므로 SDK 에 요청이 도달하지 않습니다.

### 1.4 앱 쪽 처리

앱은 이 값을 실어 보내는 것 외에 **학습 여부로 아무것도 다르게 하지 않습니다.**
캡처, 결과 파싱, 판정 기준, 이력 저장이 평상시와 완전히 같습니다.

따라서 간이 검사 결과도 정식 추론과 **같은 규칙·같은 척도**로 채워 주셔야 합니다.
확인 부탁드릴 내용은 3장에 있습니다.

---

## 2. 측정부 항목 구분 — `itemType`

### 2.1 배경

현재 요청의 `measurementPoints` 에는 좌표만 있고 **무엇을 재는 항목인지가 없습니다.**
그래서 길이와 높이를 구분할 수 없습니다. 앞서 "높이는 Width 가 아닌 Height 를 사용하면
된다"고 안내 주신 부분이 이 문제입니다.

여기에 현장에서 **내경·외경** 측정 항목 추가 요청이 들어왔습니다. 둘은 같은 문제이므로
`itemType` 한 필드로 함께 해결하려고 합니다.

### 2.2 코드표

| 코드 | 항목   | 좌표 의미             | 도형 |
|------|--------|-----------------------|------|
| 0    | 미설정 | 사용 안 함            | 없음 |
| 1    | 길이   | 선분의 두 끝점        | 선   |
| 2    | 너비   | 선분의 두 끝점        | 선   |
| 3    | 높이   | 선분의 두 끝점        | 선   |
| 4    | 두께   | 선분의 두 끝점        | 선   |
| 5    | 내경   | 원을 감싸는 사각 범위 | 사각 |
| 6    | 외경   | 원을 감싸는 사각 범위 | 사각 |

`viewName` · `viewJudge` 가 정수인 기존 계약을 따라 정수로 둡니다.
한글 문자열은 UTF-8 길이와 인코딩 문제가 있어 쓰지 않습니다.

### 2.3 좌표 사용법

`x1`, `y1`, `x2`, `y2` **네 필드를 그대로 씁니다.** 항목에 따라 해석만 달라집니다.

| 항목                            | `x1`, `y1`           | `x2`, `y2`           |
|---------------------------------|----------------------|----------------------|
| 길이 · 너비 · 높이 · 두께 (1~4) | 선분의 시작점        | 선분의 끝점          |
| 내경 · 외경 (5~6)               | 사각의 **좌측 상단** | 사각의 **우측 하단** |

내경·외경은 사용자가 원을 직접 그리지 않습니다. **원이 들어 있는 사각 범위**를
드래그로 지정합니다. 사람이 원을 정확히 그리는 것은 어렵고 재현성도 낮기 때문입니다.

사각이 정사각이 아닐 수 있으므로 **짧은 변 기준 내접원**으로 보시면 됩니다.
이 해석이 맞는지 확인 부탁드립니다.

### 2.4 요청 예시

```json
{
  "partNo": "01100-51430",
  "viewName": 6,
  "trainingRunning": 0,
  "viewJudge": 0,
  "score": 0.00,
  "scoreThreshold": 95.00,
  "dimensions": { "width": 0.00, "depth": 0.00, "height": 0.00 },
  "measurementPoints": [
    {
      "indexNo": 1,
      "itemType": 1,
      "nominalValue": 150.00,
      "toleranceMin": -0.50,
      "toleranceMax": 0.50,
      "x1": 120.50, "y1": 240.00,
      "x2": 360.50, "y2": 240.00
    },
    {
      "indexNo": 2,
      "itemType": 5,
      "nominalValue": 42.00,
      "toleranceMin": -0.20,
      "toleranceMax": 0.20,
      "x1": 180.00, "y1": 220.00,
      "x2": 420.00, "y2": 460.00
    }
  ],
  "measurements": []
}
```

`indexNo 1` 은 선분으로 재는 길이, `indexNo 2` 는 사각 범위 안의 내경입니다.

### 2.5 결과

결과 구조는 **바뀌지 않습니다.** 항목이 무엇이든 `measurements[]` 에 값 하나만
채워 주시면 됩니다.

```json
"measurements": [
  { "indexNo": 1, "measuredValue": 150.12 },
  { "indexNo": 2, "measuredValue": 42.15 }
]
```

원의 중심이나 반지름은 필요하지 않습니다. 결과 이미지의 원은 앱이 보낸 사각 범위로
그립니다. 지금 선을 그리는 방식과 같습니다.

### 2.6 내경·외경을 함께 재는 경우

동심원이라도 **측정부 두 개로 등록**합니다. 기준값과 허용이 서로 다르기 때문입니다.
같은 사각 범위를 `itemType 5` 와 `itemType 6` 두 항목이 각각 보냅니다.

### 2.7 단위

`measuredValue` 와 `dimensions` 는 **mm** 입니다. 내경·외경도 지름을 mm 로 주시면 됩니다.

## 3. 확인 부탁드릴 사항

| 번호 | 내용                                                                                                                                                            |
|------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1    | `itemType` 코드표(2.2절)에 이견이 없으신지                                                                                                                      |
| 2    | 내경·외경 좌표를 **사각 범위**로 보내는 방식(2.3절)이 처리에 문제없는지. 다른 표현이 편하시면 알려 주십시오                                                     |
| 3    | 사각이 정사각이 아닐 때 **짧은 변 기준 내접원**으로 보는 해석이 맞는지                                                                                          |
| 4    | 측정에 실패했을 때 `measuredValue` 에 무엇이 들어오는지. `0` 인지, 직전 값인지, 별도 표시가 있는지. **앱이 실패를 알아야 틀린 값을 정상으로 저장하지 않습니다** |
| 5    | 간이 검사(`trainingRunning = 1`)의 `score` 가 정식 추론과 **같은 척도**인지. 앱은 같은 `scoreThreshold` 하나로 판정합니다                                       |
| 6    | 간이 검사에서도 `measurements` 를 같은 형식으로 채워 주실 수 있는지                                                                                             |

## 4. 버퍼 영향

요청 버퍼는 8192 byte 고정입니다.

| 항목                      | 증가량     |
|---------------------------|------------|
| `trainingRunning`         | 21 byte    |
| `itemType` (측정부당)     | 약 15 byte |
| 측정부 최대 5개 기준 합계 | 약 96 byte |

측정부는 카메라별로 최대 5개이고 요청 한 번에 한 카메라만 담기므로,
한 요청의 측정부는 최대 5개입니다. 현재 실제 요청이 200 byte 안팎이라 여유는 충분합니다.

## 5. 참고 — 별도로 회신 대기 중인 건

이 문서와 별개로, `score` 척도 건을 회신 기다리고 있습니다.

사양서와 벤더 샘플은 `score` 와 `scoreThreshold` 가 모두 0~100 인데, 현재 SDK 는
`score` 를 0~1 로 돌려주고 있습니다. `scoreThreshold` 가 0보다 크면 `score` 가 항상
`0` 으로 돌아옵니다. 2026-08-24 로그에서 threshold `0.00` 호출 16건은 실제 점수
(0.23~0.998)가, `75.00` 호출 54건은 전부 `0.0` 이 반환됐고 요청 JSON 의 다른 필드는
동일했습니다.

`score` 를 0~1 로 유지하신다면 `scoreThreshold` 도 0~1 로 받도록 사양을 함께
개정해야 합니다. 한쪽만 바뀌면 지금 상태가 계속됩니다.
