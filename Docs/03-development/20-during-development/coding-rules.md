# 코딩 규칙

AI-Vision IO Inspector 개발 시 적용할 C# 코딩 원칙이다. 세부 규칙은 `AGENTS.md`와 함께 따른다.

## 기본 원칙

- 기존 동작을 먼저 확인하고, 변경 범위를 작게 유지한다.
- UI 로직, 검사 흐름, 카메라/AI/DB 연동, 파일 저장을 가능한 한 분리한다.
- Application 계층은 특정 UI 컨트롤 타입에 직접 의존하지 않는다.
- 외부 장치와 파일 입출력은 Adapter 또는 Service 뒤에 둔다.
- 오류는 사용자 메시지와 개발 로그를 구분해 남긴다.

## C# 문법 선호

- 무분별한 람다식 사용을 피한다.
- `delegate` 사용은 필요한 경우로 최소화한다.
- 사용자가 .NET Framework 4.5에 익숙하므로 명시적인 메서드, 클래스, 이벤트 처리 방식을 우선한다.
- 현재 메인 앱은 .NET Framework 4.7.2/x64 기준입니다. 최신 C# 문법보다 .NET Framework 4.5~4.7 계열에서 익숙한 명시적 문법을 우선하고, 새 문법을 사용할 때는 빌드 호환성과 유지보수 이유를 주석 또는 문서에 남깁니다.

## 주석 원칙

- 프로그램 주요 흐름과 각 함수의 기능에는 기본적으로 주석을 작성한다.
- 주석은 코드 줄의 동작을 반복하지 않고 업무 의도, 처리 흐름, 예외 상황을 설명한다.
- 카메라, AI, DB, 저장 정책처럼 장애 분석이 필요한 부분은 실패 조건과 복구 흐름을 주석으로 남긴다.

## 네이밍

| 대상 | 규칙 | 예 |
| --- | --- | --- |
| 서비스 | 역할 + `Service` | `InspectionWorkflowService` |
| 어댑터 | 외부 연동 대상 + `Adapter` | `CameraAdapter` |
| 저장소 | 대상 + `Repository` | `PartRepository` |
| 모델 | 업무 의미 중심 | `InspectionResult` |
| 화면 모델 | 화면명 + `ViewModel` | `MainInspectionViewModel` |

## 예외/로그

- 예외를 조용히 무시하지 않는다.
- 카메라 연결 실패, AI 추론 실패, DB 저장 실패는 서로 다른 오류 코드 또는 메시지로 구분한다.
- NG 판정과 시스템 오류를 혼동하지 않는다.
- 로그에는 검사 ID, 품번, 연동 대상, 실패 원인을 함께 남긴다.

## 테스트/검증

- 판정 로직과 측정값 비교는 UI 없이 테스트 가능해야 한다.
- DB 저장 전후 데이터가 일치하는지 확인한다.
- 카메라/AI 연동은 실제 장비가 없을 때 사용할 샘플 또는 Mock 경로를 준비한다.
