# 의사결정 기록

## ADR-001: 문서 구조 분리

- 날짜: 2026-05-28
- 상태: 적용
- 결정: 프로젝트 정보, 원본 자료, 요구사항, 설계, 개발 추적 문서를 폴더별로 분리한다.
- 이유: 메일, 문서, 음성 파일에서 나온 정보를 구현 작업으로 연결할 때 근거, 질문, 확정 사항을 구분하기 위해서다.

## ADR-002: 측정 항목은 측정부 목록 기반으로 설계

- 날짜: 2026-05-28
- 상태: 제안
- 결정: 길이, 너비, 높이, 두께 고정 컬럼만으로 설계하지 않고 부품별 측정부 목록 구조를 기본안으로 둔다.
- 이유: 업무파악 정리파일에서 고객이 이미지 위에 측정 부위를 선으로 지정하고 측정부 1, 2, 3 형태로 표시하는 방식을 제안했다.
- 확인 필요: 이 방식이 최종 요구사항인지 고객/PM 확인이 필요하다.

## ADR-003: 라벨/바코드 입력은 어댑터로 분리

- 날짜: 2026-05-28
- 상태: 제안
- 결정: 검사 대상 입력은 스캐너, QR/바코드, 카메라 OCR 방식이 확정되기 전까지 입력 어댑터로 분리한다.
- 이유: 입력 방식에 따라 Application 개발 범위가 달라지므로 핵심 검사 흐름과 입력 장치를 분리해야 한다.

## ADR-004: 원본 요청 처리 절차를 문서화

- 날짜: 2026-05-28
- 상태: 적용
- 결정: 신규 메일/전화/음성 요청은 `00-inbox/intake-workflow.md` 절차에 따라 접수, 요약, 반영한다.
- 이유: 고객 요청이 계속 추가될 가능성이 있어 요구사항 누락과 작업 범위 혼선을 줄이기 위해서다.
