# 의사결정 기록

## ADR-001: 문서 구조 분리

- 날짜: 2026-05-29
- 상태: 적용
- 결정: 프로젝트 정보, 원본 자료, 요구사항, 설계, 개발 추적 문서를 폴더별로 분리한다.
- 이유: 메일, 문서, 음성 파일에서 나온 정보를 구현 작업으로 연결할 때 근거, 질문, 확정 사항을 구분하기 위해서다.

## ADR-002: 측정 항목은 측정부 목록 기반으로 설계

- 날짜: 2026-05-29
- 상태: 제안
- 결정: 길이, 너비, 높이, 두께 고정 컬럼만으로 설계하지 않고 부품별 측정부 목록 구조를 기본안으로 둔다.
- 이유: 업무파악 정리파일에서 고객이 이미지 위에 측정 부위를 선으로 지정하고 측정부, 측정부2, 측정부3 형태로 표시하는 방식을 제안했다.
- 확인 필요: 이 방식이 최종 요구사항인지 고객/PM 확인이 필요하다.

## ADR-003: 라벨/바코드 입력은 어댑터로 분리

- 날짜: 2026-05-29
- 상태: 제안
- 결정: 검사 대상 입력은 스캐너, QR/바코드, 카메라 OCR 방식이 확정되기 전까지 입력 어댑터로 분리한다.
- 이유: 입력 방식에 따라 Application 개발 범위가 달라지므로 핵심 검사 흐름과 입력 장치를 분리해야 한다.

## ADR-004: 원본 요청 처리 절차를 문서화

- 날짜: 2026-05-29
- 상태: 적용
- 결정: 신규 메일/전화/음성 요청은 `00-inbox/intake-workflow.md` 절차에 따라 접수, 요약, 반영한다.
- 이유: 고객 요청이 계속 추가될 가능성이 있어 요구사항 누락과 작업 범위 혼선을 줄이기 위해서다.

## ADR-005: 기준정보/이력 DB는 SQLite로 시작

- 날짜: 2026-05-29
- 상태: 적용
- 결정: 로컬 기준정보와 검사 이력 저장소는 SQLite `Tests/AI-Vision IO Inspector/DB/DataBase.db`로 관리한다.
- 이유: 현재 요구는 단일 WPF 검사 프로그램 중심이며, 서버 설치 없이 무료로 배포/백업 가능한 DB가 적합하다.
- 구조: 부품 기준정보는 `PartList_*`, 검사 이력은 `History_*` 테이블로 분리한다.
- 초기 데이터: `export_Test.csv`는 테스트용 1회성 적재 원본이며, 앱은 실행 중 이 파일을 찾거나 읽지 않는다.
- 확장: 여러 검사 장비가 중앙 DB를 공유해야 하는 요구가 생기면 `IPartRepository`, `IInspectionRepository` 구현체만 PostgreSQL 등 서버형 DB로 교체한다.
- 위치 변경: 개발 중 DB와 기준 이미지는 상위 프로젝트 루트가 아니라 실제 관리 중인 WPF 솔루션 폴더 `Tests/AI-Vision IO Inspector/DB` 아래에 둔다.

## ADR-006: 측정용 영상 취득은 직접 카메라 SDK를 우선한다

- 날짜: 2026-05-29
- 상태: 적용
- 결정: DC-T3145G/R 카메라의 검사 원본 프레임은 카메라 SDK로 직접 취득하고, NVR/RTSP는 녹화/모니터링 보조 경로로 둔다.
- 이유: VLAD Source의 RTSP 구현은 1920x1080 고정 처리와 프레임 메타데이터 부족이 있어 5M 4:3/6:5 측정용 원본으로 바로 쓰기 어렵다.
- 확정: 2026-05-30 사용자 결정에 따라 NVR은 측정 원본이 아니라 녹화/모니터링 보조로 사용한다.
- 구현 방향: `ICameraService`를 `ICameraSource`와 `MultiCameraCoordinator` 구조로 확장하고, 프레임에는 width/height/stride/pixel format/timestamp/camera id를 포함한다.
- 확인 필요: DC-T3145G/R이 기존 `MVSDK_Net`/`IMV` 샘플과 호환되는지, 6대 동시 트리거가 필요한지, Global Shutter 2대를 어떤 ViewType에 배치할지 확인한다.
