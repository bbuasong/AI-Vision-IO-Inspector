# 개발 로드맵

## 접근 원칙

투입 초기에는 코드를 바로 수정하기보다 현재 소스, 실행 환경, DB, AI/카메라 인터페이스,
화면 구현 상태를 먼저 확인한다. 이후 고객이 바로 사용하는 메인 검사 흐름을 우선 안정화한다.

## Phase 0. 자료 정리 및 범위 확정

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 0-1 | 원본 자료 보관 및 요약 | `00-inbox/`와 `00-project/` 반영 |
| 0-2 | 요구사항 ID 부여 | `requirements.md`와 `requirement-traceability.md` 정리 |
| 0-3 | 미확정 질문 정리 | `questions.md`에 담당/상태 기록 |

## Phase 1. 현 개발 상태 파악

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1-1 | 소스 저장소 위치 및 접근 권한 확인 | VS Code/Visual Studio에서 열 수 있음 |
| 1-2 | 개발 프레임워크 확인 | C# WPF/WinForms, .NET 버전 기록 |
| 1-3 | 빌드 및 실행 확인 | 로컬에서 빌드/실행 결과 기록 |
| 1-4 | 구현된 화면과 미구현 화면 구분 | 화면별 상태를 `screen-map.md`에 반영 |
| 1-5 | DB 접속 정보와 테이블 구조 확인 | `data-model.md`를 실제 구조와 비교 |

## Phase 2. 핵심 검사 흐름 확정

| 순서 | 작업 | 완료 기준 |
