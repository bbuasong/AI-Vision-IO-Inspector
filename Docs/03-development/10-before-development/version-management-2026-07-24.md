# 소스 버전 관리 규칙

기준일: 2026-07-24

## 1. 폴더 구조

```text
AI-Vision IO Inspector/
├─ Codes/
│  ├─ Version1_0_0_0/
│  │  ├─ Backup/
│  │  │  ├─ AI-Vision IO Inspector-2026-07-20/
│  │  │  └─ AI-Vision IO Inspector/
│  │  ├─ ToolsV2/
│  │  └─ 기존 ZIP 자료
│  └─ Version1_1_0_0/
│     └─ AI-Vision IO Inspector/
├─ Docs/
└─ Tests/
```

- `Codes/Version1_0_0_0/Backup/AI-Vision IO Inspector`는 2026-07-20 기준 1.0 유지보수 프로젝트입니다.
- `Codes/Version1_1_0_0/AI-Vision IO Inspector`는 현재 기능을 포함한 1.1 개발 프로젝트입니다.
- `Tests`는 사용자가 복사 결과를 확인한 뒤 직접 정리할 원본 보존 영역입니다.
- ZIP 파일은 삭제하지 않습니다.

## 2. 버전별 책임

### Version1_0_0_0

- 기존 운영 버전의 오류 수정과 필수 안정화만 수행합니다.
- 기존 기능의 동작과 외부 인터페이스를 가능한 한 유지합니다.
- 신규 기능을 추가해야 한다면 1.0 호환 필요성이 명확한 경우에만 반영합니다.

### Version1_1_0_0

- 현재 주 개발 버전입니다.
- OCR, 고해상도 카메라, HD VLAD API 준비, 방향별 이미지 유사도 결과 등 1.1 기능을 관리합니다.
- 1.0의 공통 오류 수정 중 1.1에도 필요한 항목을 선별해 반영합니다.

## 3. 변경 반영 방향

1. 1.0에서 수정한 공통 오류는 1.1에도 필요한지 검토합니다.
2. 필요한 수정만 파일 또는 커밋 단위로 1.1에 적용합니다.
3. 1.1 전용 기능은 1.0으로 역반영하지 않습니다.
4. 버전 폴더 전체를 다른 버전에 덮어쓰지 않습니다.
5. 동일 파일이 양쪽에서 변경되었으면 자동 복사하지 않고 diff를 확인해 수동 병합합니다.

권장 커밋 표기:

- `[v1.0]` 1.0 전용 수정
- `[v1.1]` 1.1 전용 수정
- `[shared]` 두 버전에 모두 필요한 공통 수정

## 4. 공통 수정 반영 절차

1. 1.0에서 수정 범위와 원인을 기록합니다.
2. 1.0 전체 솔루션을 `Debug|x64`로 빌드합니다.
3. 변경 파일 또는 커밋만 1.1에 적용합니다.
4. 1.1의 기존 기능이 덮어써지지 않았는지 diff로 확인합니다.
5. 1.1 전체 솔루션을 `Debug|x64`로 다시 빌드합니다.
6. 카메라, OCR, DB, VLAD 관련 변경은 해당 장비 또는 테스트 모드로 별도 검증합니다.
7. `changelog.md`와 `work-log.md`에 날짜와 적용 버전을 기록합니다.

## 5. 금지 사항

- 1.1 프로젝트 전체를 1.0 폴더에 덮어쓰지 않습니다.
- 1.0 프로젝트 전체를 1.1 폴더에 덮어쓰지 않습니다.
- `bin`, `obj`, `.vs` 산출물을 소스 변경으로 판단하지 않습니다.
- DLL, Config, DB를 버전 간 무조건 복사하지 않습니다. 각 버전의 계약과 실행 환경을 먼저 확인합니다.
- 실제 운영 DB와 이미지 폴더를 소스 병합 대상으로 취급하지 않습니다.
