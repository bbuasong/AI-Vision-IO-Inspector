# Version 1.1.0.0 병합 검토

기준일: 2026-07-24

## 1. 병합 대상

- 기준 백업: `Tests/Backup/AI-Vision IO Inspector-2026-07-13`
- 기능 백업: `Tests/Backup/AI-Vision IO Inspector-2026-07-20`
- 적용 대상: `Tests/AI-Vision IO Inspector`
- 적용 버전: `1.1.0.0`
- 대상 프레임워크/플랫폼: `.NET Framework 4.7.2`, `x64`

현재 프로젝트의 OCR, 고해상도 카메라 설정, 두 VladId 및 HD JSON API 준비 코드는 유지하면서 두 백업 사이의 변경을 3-way 방식으로 비교했습니다. 백업에만 있는 변경을 현재 프로젝트에 그대로 덮어쓰지 않고, 현재 코드와 충돌하는 UI/ViewModel/Config/Vision 수명주기 코드는 기능 단위로 병합했습니다.

## 3. 주요 충돌 처리

### UI와 ViewModel

- 2026-07-20의 기준 이미지 확대, 유사도 검사, Score 설정 UI를 적용했습니다.
- 현재 프로젝트의 OCR 탭, 고해상도 카메라 정보, HDD/학습 관리 UI는 유지했습니다.
- `MainWindowViewModel`은 OCR 명령과 유사도/팝업/Score 명령을 함께 유지하도록 병합했습니다.

### Vision

- 현재 프로젝트의 두 VladId와 새 HD API fallback 구조를 유지했습니다.
- RTSP callback은 최신 프레임 캐시만 갱신하고, 네이티브 추론은 검사 요청 시 한 번만 수행하도록 유지했습니다.
- 반복 callback 추론으로 `ptxas.exe`와 네이티브 호출이 계속 발생하던 백업 흐름은 적용하지 않았습니다.

### Config와 실행 경로

- 모든 실행 설정은 배포 EXE 옆 `CFG`를 기준으로 읽고 저장합니다.
- 현재 `GPU_ID=0`, OCR, 카메라 해상도/위치 설정을 유지했습니다.
- 검사 Score 기본값 `95.00`, 단일품목 유사도 기본값 `99.00`을 추가했습니다.

## 5. 결정이 필요한 충돌 항목

### 결과 이미지 주석

권장 방향은 카메라 원본과 기준 이미지를 수정하지 않고, 검사 결과용 복사본에만 W/D/H와 측정부 측정값을 그리는 방식입니다. 표시 위치와 값의 출처는 새 HD 결과 JSON의 `dimensions`와 `measurements[]`를 사용합니다.

### 실행 중 카메라 실패

권장 방향은 활성 카메라가 실패하면 해당 채널을 `ERROR`로 기록하고 나머지 채널 검사를 계속하되, 최종 결과는 `PASS`가 아닌 `ERROR`로 처리하는 것입니다. 자동으로 비활성화하고 PASS 판정에서 제외하면 실제 검사 누락을 정상으로 오인할 수 있습니다.

### 6장 합성 이미지

`VLAD_HD_ImageMerge(char* inputPath, char* keyId, char* outputPath)`의 x64 export와 입력 폴더/출력 파일 규칙이 확정된 후 연결합니다. API가 없는 현재 DLL에 가상 구현을 추가하지 않습니다.
