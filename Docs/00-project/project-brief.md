# 프로젝트 브리프

## 프로젝트명

HD현대사이트솔루션 AI 비전 기반 입고검사 시스템

## 목적

입고된 부품의 외관, 라벨/품번, 기준 이미지, 측정값을 비교하여 오입고 또는 오출고로
이어질 수 있는 불일치를 사전에 검출한다.

## 핵심 기능

| 구분 | 내용 | 상태 |
| --- | --- | --- |
| 부품 기준정보 관리 | 품번, 품명, 분류코드, 분류설명, 구분, 측정 기준값, 기준 이미지 등록 | 요구 |
| 검사 실행 | 라벨 또는 품번 입력 후 카메라 촬영, AI 추론, 치수 측정 수행 | 요구 |
| OK/NG 판정 | 기준정보와 촬영/측정 결과를 비교해 Good 또는 NG 표시 | 요구 |
| 이력 저장 | 검사 결과, NG 이미지, 불일치 부위, 이벤트 로그 저장 | 요구 |
| 이력/통계 조회 | 검사 이력, 등록 부품 수, 기간별 검사 실적, OK/NG 수, 오류수 조회 | 추가 요청 |
| 엑셀 일괄등록 | 품번체계 변경에 대비한 기준정보 대량 등록 | 추가 요청 |

## 역할 이해

현재 자료 기준으로 개발 투입 역할은 AI 모델 자체 개발보다 C# Application 개발 지원에 가깝다.

담당 가능성이 높은 범위는 다음이다.

- 화면 개발: 메인 검사, DB 조회/확인, 부품등록, 이력, 통계, 옵션
- 카메라 SDK 연동: 촬영, 이미지 표시, 촬영 실패 처리
- AI 연동: 추론 호출, 결과 수신, 화면/DB 반영
- DB 연동: 부품 기준정보, 측정부, 검사 이력, 이벤트 저장
- 파일 관리: 검사 이미지, NG 이미지, 로그, 저장공간 정책
- 엑셀 일괄등록: 기준정보 대량 업로드와 검증

## 지금 가장 먼저 알아야 할 내용

1. 현재 소스코드 위치와 빌드 가능 여부
2. 개발 프레임워크: C# WPF인지 WinForms인지
3. DB 종류: SQLite 확정, 실제 테이블 구조는 PartList_*, History_* 기준
4. 카메라 SDK 문서, 샘플 코드, 장비 연결 방식
5. AI 모델 호출 방식: 현재는 VLAD_SDK.dll을 WPF 프로세스 내부에서 호출. 결과 문자열 계약은 `true/false,score,measurement1...N`으로 정리됐고, 최종 모델 구조와 실제 DLL 반환 위치는 AI 담당자 확인 필요
6. 라벨/바코드 입력 방식: 스캐너 입력, QR/바코드 인식, 카메라 OCR 중 무엇인지
7. 측정부는 길이/너비/높이/두께 고정 1세트가 아니라 `측정부1`~`측정부5` 독립 구조로 관리
8. 검사 이력 저장 정책: `OUTPUT_PATH` 기준 일 단위 삭제 후보 계산, HDD 여유공간/설정기간 조건, 사용자 확인 팝업 구조로 구현 후 실제 저장장치 검증 필요
9. 6월 말 셋업 범위에 엑셀 일괄등록, 통계가 포함되는지
