- HD현대사이트솔루션 AI 비전 기반 입고검사 시스템
업무 파악 정리
- 1. 작성 목적
- ▣ AI 모델 개발자가 아니라, AI 모델·카메라·DB·검사 결과를 연결하는 C# Application 개발 지원 역할로 투입되는 흐름으로 판단됩니다.
- 2. 메일 검토 결과
- ▣ 첫 번째 메일은 인력 투입과 역할 배정의 근거이고, 두 번째 메일은 실제 개발 요구사항과 고객 추가 요청사항을 파악하기 위한 핵심 자료입니다.
- 3. 프로젝트 개요
- · 카메라를 이용해 입고 부품의 외관 이미지를 촬영
- · 등록된 기준 이미지 및 기준정보와 실제 입고 부품을 비교
- · AI 추론 결과 및 치수 측정값을 이용해 OK/NG 판정
- · NG 발생 시 불일치 부위와 검사 이력을 저장
- · 신규 부품 등록, 기준정보 수정, 검사 이력 조회, 통계정보 확인 기능 제공
- ▣ 종합하면, 이 시스템은 부품 등록, 검사 실행, AI/치수 판정, 검사결과 저장, 이력/통계 조회가 하나의 업무 흐름으로 연결되는 Application 성격이 강합니다.
- 4. 현재 진행 일정
- ▣ 종합하면, 일정상 큰 이슈는 없다고 공유되었으나, 추가 요구사항이 계속 발생하고 있어 실제 개발 범위 확정이 중요합니다.
- 5. 주요 요구사항 정리
- 첫째, 부품 기준정보 등록 기능입니다.
- 신규 부품을 DB에 등록하고, 품번·품명·분류코드·분류설명·구분·측정 기준값 등을 관리해야 합니다. 고객은 향후 품번체계 변경에 대비하여 엑셀을 통한 일괄등록 기능도 요청하였습니다.
- 둘째, 메인 검사 기능입니다.
- 라벨 또는 바코드 입력을 통해 검사 대상 부품을 조회하고, 카메라 촬영 후 AI 추론 및 치수 측정을 수행하여 OK/NG 판정 결과를 표시해야 합니다.
- 셋째, 검사결과 이력 관리 기능입니다.
- 검사일, 품번, 품명, 분류코드, 분류설명, 구분, 측정값, NG 시 불일치 부위 정보를 저장하고 조회할 수 있어야 합니다. 저장기간은 기존 1개월 저장 방식에서 저장공간 기준 삭제 방식으로 변경 검토 중입니다.
- 넷째, 측정부 표시 방식 변경 요청입니다.
- 고객은 길이, 너비, 높이, 두께처럼 고정 항목으로 표시하기보다 이미지 위에 측정이 필요한 부위를 선으로 지정하고, 해당 항목을 측정부 ①, 측정부 ②, 측정부 ③ 형태로 표시하는 방식을 제안하였습니다.
- 다섯째, 통계정보 추가 요청입니다.
- 총 등록 부품수, 검사실적, 검사 품목, OK/NG 수, 평균 검사시간 등의 통계정보를 확인할 수 있는 기능이 요청되었습니다.
- ▣ 종합하면, 요구사항 중 가장 주의해야 할 부분은 측정 항목을 고정 컬럼으로 설계하지 않고, 측정부 단위로 확장 가능한 구조를 고려해야 한다는 점입니다.
- 6. Application 개발 관점 업무 범위
- 송영준 프로가 맡게 될 가능성이 높은 업무는 AI 모델 자체 개발보다는 Application 개발 영역입니다. 즉, AI 모델과 카메라 SDK, DB, 검사 화면, 이력 저장을 연결하는 역할이 핵심입니다.
- ▣ 종합하면, 업무 범위는 단순 화면 개발로만 보기 어렵고, 검사 업무 흐름 전체를 Application에서 안정적으로 연결하는 개발로 이해하는 것이 적절합니다.

- 10. 개발 시 주의해야 할 사항
- 첫째, 측정 항목을 고정 구조로 설계하지 않도록 주의해야 합니다.
- 고객이 제안한 측정부 ①, ②, ③ 방식은 측정 포인트가 부품마다 달라질 수 있음을 의미합니다. 따라서 Length, Width, Height, Thickness와 같은 고정 컬럼보다는 측정부 목록을 별도 관리하는 구조가 필요할 수 있습니다.
- 둘째, 요구사항 명세서와 최신 회의 메일 간 차이를 구분해야 합니다.
- 요구사항 명세서는 기본 골격이고, 5/26 점검회의 결과 메일은 최신 추가 요청사항입니다. 따라서 개발 기준을 잡을 때 두 자료를 함께 보고, 변경된 내용은 별도 확인이 필요합니다.
- 셋째, 바코드/라벨 이슈는 아직 확정되지 않았습니다.
- 스캐너 입력 방식인지, QR/바코드 인식인지, 카메라 기반 라벨 인식인지에 따라 Application 개발 범위가 달라집니다. 이 부분은 고객 IT 확인 결과를 반드시 반영해야 합니다.
- 넷째, 검사 이력 저장 정책은 DB 및 파일 저장 구조에 직접 영향을 줍니다.
- 1개월 자동삭제 방식과 저장공간 기준 삭제 방식은 구현 방식이 다르므로, 최종 정책 확정 전에는 확장 가능한 구조로 설계하는 것이 안전합니다.
- ▣ 종합하면, 개발 리스크는 기능 구현 자체보다 미확정 요구사항을 고정 구조로 먼저 만들어버리는 데서 발생할 가능성이 높습니다.
- 11. 최종 정리
- HD현대사이트솔루션 AI 비전 기반 입고검사 시스템은 입고 부품의 기준정보 등록, 검사 실행, AI/치수 판정, 결과 저장, 이력/통계 조회까지 이어지는 업무형 Application 개발 과제입니다.
- 송영준 프로는 C# Application 개발자로 투입되는 흐름이며, AI 모델 개발보다는 AI 모델 결과와 카메라 촬영, DB 기준정보, 검사 이력, 화면 UI를 연결하는 역할이 핵심입니다.
- 따라서 신규 투입 초기에는 현재 소스 구조와 실행 환경을 먼저 확인하고, 이후 담당 화면과 연동 범위를 명확히 한 뒤 고객 추가 요구사항을 우선순위에 맞게 반영하는 방식으로 접근하는 것이 좋습니다.
- ▣ 종합하면, 본 과제의 핵심은 “부품 등록 → 검사 실행 → AI/치수 판정 → 결과 저장 → 이력/통계 확인”의 전체 업무 흐름을 안정적으로 구현하는 것입니다.
