# 인수 기준

요구사항이 실제로 완료됐는지 판단하기 위한 기준이다. 구현 작업을 시작하거나 완료 처리할 때 이 문서를 함께 확인한다.

## 공통 완료 기준

| ID | 기준 | 확인 방법 |
| --- | --- | --- |
| AC-001 | 요구사항 ID가 `requirements.md`와 연결되어 있다. | 요구사항 추적표 확인 |
| AC-002 | 화면, DB, 파일, 연동 영향이 문서에 반영되어 있다. | `02-design/` 문서 확인 |
| AC-003 | 미확정 항목은 구현 확정으로 처리하지 않았다. | `03-development/questions.md` 확인 |
| AC-004 | 정상 흐름과 실패 흐름이 모두 확인되었다. | 테스트/시연 결과 확인 |
| AC-005 | 사용자가 의도를 파악할 수 있도록 주요 함수와 흐름에 주석이 있다. | 코드 리뷰 확인 |

## 메인 검사 흐름

| ID | 기준 | 상태 |
| --- | --- | --- |
| AC-MAIN-001 | 라벨/품번 입력으로 검사 대상 부품을 조회할 수 있다. | 대기 |
| AC-MAIN-002 | 기준정보와 기준 이미지가 화면에 표시된다. | 대기 |
| AC-MAIN-003 | 카메라 촬영 결과가 화면에 표시된다. | 대기 |
| AC-MAIN-004 | AI 추론 결과와 측정값이 판정 로직에 반영된다. | 대기 |
| AC-MAIN-005 | OK/NG 결과와 NG 사유가 명확히 표시된다. | 대기 |
| AC-MAIN-006 | 검사 결과, 이미지 경로, 이벤트 로그가 저장된다. | 대기 |

## 부품 기준정보 관리

| ID | 기준 | 상태 |
| --- | --- | --- |
| AC-PART-001 | 품번, 품명, 분류코드, 분류설명, 구분을 등록할 수 있다. | 대기 |
| AC-PART-002 | Top/Front/Back/Left/Right/Thickness 기준 이미지를 관리할 수 있다. | 대기 |
| AC-PART-003 | 부품별 측정부를 동적으로 등록할 수 있다. | 대기 |
| AC-PART-004 | 등록된 기준정보를 검색, 수정, 삭제할 수 있다. | 대기 |
| AC-PART-005 | 중복 품번, 누락 필드, 잘못된 측정값이 검증된다. | 대기 |

## 이력/통계

| ID | 기준 | 상태 |
| --- | --- | --- |
| AC-HIS-001 | 기간, 품번, 결과 기준으로 검사 이력을 조회할 수 있다. | 대기 |
| AC-HIS-002 | NG 결과에서 불일치 부위와 저장 이미지를 확인할 수 있다. | 대기 |
| AC-HIS-003 | 저장 정책에 따라 오래된 이력 또는 이미지가 관리된다. | 확인 필요 |
| AC-STAT-001 | 등록 부품 수, 검사 실적, OK/NG 수, 평균 검사시간을 확인할 수 있다. | 추가 요청 |
