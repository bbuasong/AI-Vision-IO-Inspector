# Codex 작업 지침

이 저장소에서 Codex는 HD현대사이트솔루션 AI 비전 기반 입고검사 시스템의
문서 정리, 요구사항 분석, 설계, 개발 보조자로 동작합니다.

## 커뮤니케이션

- 기본 응답 언어는 한국어입니다.
- 사용자의 원본 메일, 첨부 문서, 정리 문서, 음성 파일은 근거 자료로 취급합니다.
- 불명확한 내용은 임의 확정하지 않고 `03-development/questions.md`에 질문으로 남깁니다.

## 문서 관리

- 프로젝트 핵심 정보: `00-project/`
- 원본 자료 및 신규 요청 접수: `00-inbox/`
- 요구사항: `01-requirements/`
- 설계: `02-design/`
- 작업 추적: `03-development/`
- 회의록: `04-meetings/`
- `work-log.md`, `changelog.md`, `decisions.md`, `task-board.md`, `intake-log.md`처럼 누적되는 Markdown 파일을 업데이트할 때는 변경 당일 날짜를 명시합니다.
- 날짜별로 누적되는 문서는 먼저 오늘 날짜 섹션을 확인하고, 없으면 새 섹션을 만든 뒤 그 아래에 변경 내용을 기록합니다.

## 작업 방식

1. 코드를 수정하기 전에 관련 문서를 먼저 확인합니다.
2. 새 요구사항은 요구사항 문서에 추가하고, 미확정 사항은 질문 문서에 추가합니다.
3. 의미 있는 설계 선택은 의사결정 기록에 남깁니다.
4. 기존 파일을 정리할 때는 원본을 보존하고, 이동 또는 이름 변경 범위를 명확히 기록합니다.
5. 테스트, 빌드, 실행 결과는 최종 응답에 간단히 요약합니다.

## 변경 승인 절차

- 코드, XAML, 설정, 문서 파일을 수정하기 전에는 변경 예정 파일, 변경 목적, 주요 변경 내용, 예상 영향, 검증 방법을 간단히 공유합니다.
- 작업 완료 후에는 변경 범위 확인, 빌드/검증, Git 커밋, GitHub 푸시를 기본 마무리 절차로 수행합니다.
- 사용자가 명시적으로 사전 승인을 요청한 작업은 `적용` 확인을 받은 뒤 파일을 수정합니다.
- 사용자가 `거절` 또는 수정 방향 변경을 요청하면 파일을 수정하지 않고 변경안을 다시 정리합니다.
- 적용 후에는 수정된 파일 목록과 핵심 변경 내용을 요약하고, 가능한 경우 빌드 또는 검증 결과를 함께 보고합니다.
- 커밋 전에는 `git status`와 관련 diff를 확인하고, 기존 사용자 변경과 이번 작업 변경이 섞여 있으면 이번 작업 범위 파일만 선별해 저장합니다.

## C# 개발 스타일

- 무분별한 람다식 사용을 피합니다.
- `delegate` 사용은 필요한 경우로 최소화합니다.
- 현재 메인 앱은 .NET Framework 4.7.2/x64 기준입니다. 사용자가 .NET Framework 4.5를 오래 사용했던 점을 고려해, 최신 C# 축약 문법보다 .NET 4.5에서 익숙한 명시적인 코드를 선호합니다.
- 최신 문법을 사용해야 할 때는 호환성, 가독성, 유지보수상 이유를 명확히 합니다.
- 프로그램의 주요 흐름과 각 함수의 기능에는 기본적으로 주석을 작성해 사용자가 의도를 쉽게 파악할 수 있게 합니다.
- 주석은 코드가 무엇을 하는지 반복 설명하기보다, 왜 필요한지와 어떤 업무 흐름을 처리하는지 중심으로 작성합니다.

## 신규 메일/전화/음성 요청 처리

1. 원본 파일을 `00-inbox/`의 적절한 하위 폴더에 보관합니다.
2. `00-inbox/intake-log.md`에 접수 기록을 추가합니다.
3. 메일/통화/음성 요약은 `00-inbox/summaries/`에 Markdown으로 작성합니다.
4. 구현이 필요한 내용은 `03-development/task-board.md`에 작업 항목으로 연결합니다.
5. 요구사항 변경은 `01-requirements/requirements.md`와 `01-requirements/requirement-traceability.md`에 반영합니다.
6. 확인이 필요한 내용은 `03-development/questions.md`에 남깁니다.

## 금지 사항

- 사용자가 명시하지 않은 원본 자료 삭제
- 관련 없는 대규모 리팩터링
- 확인되지 않은 외부 요구사항을 확정 사실처럼 문서화
